# Phase 3B Doctrine Approval Reuse Scan V1

Status: IMPLEMENTATION SELECTION RECORD.

## Requirement

Add a local source-review path that can promote a source-mapped draft DoctrineUnit through one explicit Calvin or authorized-agent approval. Preserve public-source provenance and keep RAG, embeddings, providers, private corpus access, and trading behavior absent.

## Reuse selection

The implementation reuses the existing project seams:

- `SourceV1`, `DoctrineUnitV1`, canonical hashing, exact runtime validation, and approved-only RAG projection;
- content-hashed PostgreSQL migrations, append-only triggers, restricted `pa_app` grants, PGlite conformance, and real PostgreSQL verification;
- Fastify, generated JSON Schema/OpenAPI, bounded strict JSON, loopback Host/Origin checks, and existing operator/reviewer bearer principals;
- the Case CLI transport and the React/Vite/Router/TanStack Query Research Console;
- Node, Vitest, Testing Library, and Playwright test paths;
- agent-reach Web, YouTube, sitemap, and search paths for read-only public URL discovery.

No new runtime or development dependency is required.

## Rejected additions

- Multi-agent voting, quorum, blind doctrine review, and a generic workflow engine add process without a V1 requirement.
- A crawler service, queue, scheduler, or browser automation package is unnecessary for a frozen public snapshot.
- A second database, vector database, RAG framework, XML runtime parser, and generated API client duplicate existing seams.
- Public deployment auth, OIDC, sessions, and remote corpus services remain outside the local-only contract.

## Boundary

The URL inventory is discovery metadata. Only an exact deployment-authorized proposal can enter the approval store. One authenticated principal performs one explicit approval; generated content is never promoted merely because it was proposed. Approval creates no embeddings and grants no model, replay, Paper, Live, exchange, or execution authority.
