# ADR-0023: Brooks Semantic Coverage Before Provider Evaluation

Status: ACCEPTED SEQUENCING DECISION. NO IMPLEMENTATION OR OPERATIONAL AUTHORITY.

## Context

PA Agent Lab has progressed to an accepted fake-only Phase 5B2B provider-adapter foundation, an accepted four-rule Prompt Package V2 geometry correction, and separate exact-content approval of Prompt Package V2. No V2 activation or preparation, installed-CLI invocation, provider call, runtime model record, production BrooksDecision, or real Case exists.

The engineering path reached that boundary through an intentionally small vertical slice. The current Doctrine activation contains the exact nine public pilot DoctrineUnits. The pilot artifact explicitly says it is not a complete corpus and records known coverage gaps. Phase 4A proved complete approved/unretired projection, lexical retrieval, quality evidence, activation, and retirement behavior, but its exit gate requires only a non-empty exact approved snapshot. Its implementation also fixes six Source identities and a quality suite that exactly covers the nine-unit pilot.

Consequently, three progress claims must remain separate:

1. engineering infrastructure has reached the offline Phase 5B2B foundation;
2. Brooks semantic content has reached only the Phase 3B/4A public pilot;
3. external execution and formal semantic evaluation have not started.

Treating those as one linear completion claim would overstate Brooks competence and could produce a new prepared payload whose only Doctrine authority is the known incomplete pilot.

## Decision

### Preserve completed work

All accepted Phase 0 through Phase 5B2B contracts, implementations, immutable execution evidence, geometry correction, and exact Prompt Package V2 content approval remain valid within their recorded boundaries. They are not rolled back, rewritten, or reclassified as model-quality evidence.

The existing V1 activation and prepared payload remain immutable historical plumbing evidence. They do not establish a coverage-complete Brooks baseline or authorize reuse for formal evaluation.

### Pause provider progression

Prompt Package V2 activation and preparation, installed-CLI inference, every external provider call, and every ModelRun/ProviderAttempt/production BrooksDecision operation remain paused until the semantic and evaluation prerequisites below are separately designed, accepted, implemented, and verified.

Offline privacy/capability research may be proposed separately, but this sequencing decision grants no authority to run either provider CLI.

### Phase 3C: V1 Brooks semantic coverage baseline

A new Phase 3C must define a finite, auditable V1 Brooks semantic coverage baseline before additional Doctrine extraction or approval.

The baseline is coverage-complete only for the accepted BrooksDecision V1 policy surface. It is not a claim to exhaust all Al Brooks teaching or all Price Action knowledge. Its future contract must bind at least:

- the V1 decision layers and doctrine concepts that require source support;
- required positive rules, counterexamples, conflict/ambiguity treatment, and no-trade/uncertainty boundaries;
- exact eligible public Source classes and selected Source snapshots;
- source locators, content hashes, derived-wording review, and gap disposition;
- completion, rejection, retirement, and residual-gap criteria;
- outcome blindness and exclusion of protected windows, private material, unauthorized V6 content, model-generated authority, Calvin review, outcomes, and PnL.

The frozen public URL inventory remains discovery metadata. Its 182 `doctrine_candidate` URLs are not a bulk-ingestion target and confer no proposal, approval, or retrieval authority. Exact read-only source access, extraction, proposal creation, and approval batches require separate authorization.

### Phase 4A2: expanded corpus activation

After Phase 3C content approval, a separately accepted Phase 4A2 contract must project the expanded exact approved/unretired set through the existing append-only corpus platform. It must separately authorize and verify:

- the expanded exact Source allowlist;
- a quality suite that covers the complete target snapshot rather than the fixed nine-unit pilot;
- deterministic ingestion, passed quality evidence, explicit activation, and retirement fail-closed behavior;
- an immutable coverage acceptance record binding the exact snapshot and residual gaps.

Phase 4B embeddings and vector/hybrid retrieval are not prerequisites by default. They remain optional and require separate evidence and authority.

### Post-corpus assembly gate

The current full-corpus Policy Assembly accepts at most 32 Doctrine records and fails closed above that bound. After the Phase 4A2 snapshot is known:

- if the complete target snapshot remains within all accepted full-corpus bounds, a separately authorized new assembly may continue to use the complete snapshot;
- otherwise, Selector V2 or a separately justified assembly-contract revision must be accepted and implemented before any new prepared payload.

The corpus must never be truncated, sampled, or silently omitted to fit the existing boundary.

### Provider and evaluation ordering

After the expanded corpus and assembly path are accepted, the remaining order is:

1. generate a new immutable PolicyAssembly and Prompt Package V2 prepared payload under separate lifecycle authorization;
2. complete installed-CLI privacy, isolation, hidden-retry, PNG-transport, output-protocol, terminal-authority, process-lifecycle, global-concurrency, and persistence gates;
3. define and accept the Phase 6 real-Case read-only ingestion boundary, protected-window exclusion, frozen outcome-blind sample, candidate symmetry, semantic adjudication rubric, thresholds, and falsification criteria before provider outputs are inspected;
4. separately authorize at most one synthetic transport-smoke call that is permanently excluded from formal evaluation;
5. execute the symmetric Phase 6 semantic bakeoff only under its accepted frozen contract.

Phase 7 training remains optional after prompt/RAG/schema evaluation. Phase 8 replay remains downstream of frozen validated decisions. Phase 9 independent research remains downstream of an independently evaluated Brooks baseline. None implies Paper, Live, exchange, wallet, order, or real-money authority.

## Not authorized

This ADR does not authorize:

- opening, fetching, refreshing, crawling, extracting, storing, or summarizing any Source;
- creating, inserting, approving, retiring, ingesting, activating, rolling back, or querying any additional Doctrine record or corpus;
- changing contracts, schemas, migrations, code, tests, dependencies, services, deployment, credentials, or provider configuration;
- Prompt Package V2 activation, rollback, payload preparation, installed-CLI inference, provider calls, ModelRuns, ProviderAttempts, runtime audits, model responses, or production BrooksDecisions;
- real Case or market-data access, protected-window access, outcomes, evaluation execution, replay, training, Paper, Live, exchange, wallet, order placement, or trading.
